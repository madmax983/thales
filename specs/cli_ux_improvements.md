# 🔭 Vantage: Spec for CLI UX Improvements (Feedback & Piping)

## 1. The "User Story"
*   **Story A (Feedback):** "As a Trader, I want to see *why* no signals were generated in the JSON output, so that I don't confuse a quiet market with a broken tool."
*   **Story B (Piping):** "As a Developer, I want to output raw data (without the JSON envelope), so that I can easily pipe results into other tools like `jq` or `execute-intent` without parsing overhead."

## 2. The "So What?" (Business Value)
*   **Trust:** Users abandon tools that fail silently. Explicit warnings build trust.
*   **Composability:** The Unix philosophy relies on piping. Envelopes break simple piping.
*   **Gap Analysis:** `DX_AUDIT_REPORT.md` explicitly complains about these two issues ("Silent Failure" and "JSON Envelope Overhead").

## 3. Acceptance Criteria

### ✅ Must Have (MVP)
1.  **Response Envelope Warnings:**
    *   Commands returning `ResponseEnvelope` must populate the `warnings` field when the operation succeeds but has caveats (e.g., empty signal list).
    *   Specific Case: `generate-signals` must warn if:
        *   No signals were generated by the strategy.
        *   Signals were generated but filtered (low confidence, daily limit, etc.).
2.  **Raw Output Flag:**
    *   Add global flag: `--raw`.
    *   When `--raw` is present:
        *   Do not wrap output in `ResponseEnvelope`.
        *   Print the JSON serialization of `data` directly.
        *   If `data` is a list, print the list.
        *   If error, print error to stderr and exit with non-zero code.

## 4. Interface Design

### CLI Example (Warnings)
```bash
$ cargo run ... generate-signals ...
{
  "status": "ok",
  "errors": [],
  "warnings": ["Strategy 'BollingerBands' generated 0 signals for latest timestamp."],
  "data": []
}
```

### CLI Example (Raw)
```bash
$ cargo run ... generate-signals ... --raw
[]
```

```bash
$ cargo run ... fetch-market-data ... --raw
{
  "schema_version": "v0",
  "bars": [...]
}
```
