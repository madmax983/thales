# 🔭 Vantage: Spec for Missing Signal Structure in Market Analysis

## 👤 User Story
As a Quantitative Trader, I want the market analysis reports generated by the `analyze-market` command to include a standardized, parsable trade signal structure, so that my execution pipelines can automatically interpret analysis recommendations into concrete trade intents without failing.

## 💡 So What?
When automated pipelines (like `execute_cycle.py`) rely on text-based market analysis reports to generate trade intents, they require a deterministic structure. Currently, valid market analysis is being rejected downstream (as seen in `trade_rejections.md` for AAPL) because the report lacks a clear, programmatic signal structure. Fixing this ensures that analytical work directly translates into execution, reducing missed opportunities and manual intervention.

## 📈 Metric Definition
Success = 0 "Analysis report found but no actionable trade signal structure" errors in `trade_rejections.md` for assets with generated market analysis, and a 100% parse rate for the signal structure block downstream.

## 🔍 Gap Analysis
Currently, the `analyze-market` command generates a comprehensive market analysis report (Regime, Sentiment, Volatility) and logs it to `Signals.md`. However, the report is primarily designed for human readability or high-level context. Downstream execution scripts expect a specific JSON block or structured text format detailing actionable signal parameters (e.g., direction, confidence, suggested size, stop loss, take profit) that is currently missing or inconsistently formatted, leading to execution failures despite valid analysis.

## ✅ Acceptance Criteria
- The output of `analyze-market` (and its corresponding entry in `Signals.md`) must include a dedicated, standardized `Signal Structure` block.
- This block must be consistently formatted (e.g., as a JSON code block) containing required fields for execution: target symbol, market, recommended side (buy/sell), confidence score, and suggested stop loss / take profit levels.
- The structure must be strictly enforced so that downstream parsers can extract the intent without ambiguity.
- If the analysis concludes that no trade should be taken, the block must explicitly state a "hold" or "neutral" recommendation rather than omitting the structure entirely.

## 🚫 Out of Scope
Implementation of the new signal structure output in the CLI source code or modifying the `execute_cycle.py` parser logic.
